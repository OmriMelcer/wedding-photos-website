# Milestone v1.1: Security & Hardening

**Status:** ✅ SHIPPED 2026-05-18

## Overview

Hardened the live wedding photo album against privacy leaks and cost-incurring attacks before sharing the URL with guests. All photos were regenerated with EXIF stripped, re-uploaded with CDN-ready cache headers, and Cloudflare spending guardrails were configured.

## Milestone Summary

**Key Accomplishments:**

1. EXIF stripping via `exif=b""` on all resize output — GPS coordinates and device identifiers removed from 1309 live photos
2. CDN-ready Cache-Control headers baked into upload.py: `max-age=86400` for metadata.json, `max-age=31536000, immutable` for all photo/thumbnail objects
3. Cloudflare billing guardrails: $5/month budget alerts on R2 operations and Workers requests
4. Full re-upload of 1309 photos with EXIF stripped and correct headers verified live on R2
5. 17 automated tests (TDD) cover all security requirements — 6 resize + 3 upload + 8 pre-existing

**Key Decisions:**

- CF-03 (WAF rate limiting) descoped — Workers.dev free tier can't use rate limit rules; built-in DDoS is sufficient for a 100-guest site
- EXIF stripping via `exif=b""` kwarg (not post-process) — simpler, Pillow-native, orientation correction runs before strip
- Cache-Control set as S3 ExtraArgs (`CacheControl` key) — no post-upload metadata patch needed

**Issues Resolved:**

- Photos previously had GPS coordinates and device identifiers live on R2 — now stripped
- R2 objects had no Cache-Control — CDN could not cache; now correctly set

**Issues Deferred:**

- None — all v1.1 scope delivered

**Technical Debt Incurred:**

- Phase 7 had no formal PLAN.md/SUMMARY.md (Cloudflare dashboard config is not scriptable at current scale)
