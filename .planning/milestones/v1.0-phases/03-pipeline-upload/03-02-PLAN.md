<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env vars → boto3 client | R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY are operator-supplied secrets; never written to disk or printed |
| local filesystem → R2 | Files uploaded from pipeline/output/; filename security guard rejects path-traversal characters before S3 key construction |
| metadata.json → React site | URL fields written by upload.py are the source of truth for every image src the site renders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Information Disclosure | upload.py credential handling | mitigate | Credentials read from env vars only; never printed or logged; boto3 client constructed in _make_s3_client(); verified: no hardcoded key strings in source |
| T-03-04 | Tampering | S3 key construction from filename | mitigate | Security guard rejects filenames with "/" or ".." before key construction — same pattern as resize.py; path-traversal into R2 namespace prevented |
| T-03-05 | Denial of Service | ThreadPoolExecutor with 2618 concurrent uploads | accept | MAX_WORKERS=16 limits concurrency; Cloudflare R2 rate limits are generous for this volume; one-shot script, not a service |
| T-03-06 | Repudiation | Overwriting R2 objects silently | accept | D-04 requires unconditional overwrite (one-shot philosophy); operator re-runs the full pipeline if output is wrong |
| T-03-SC | Tampering | boto3 package install | mitigate | boto3 is the official AWS SDK (pypi.org/project/boto3, published by Amazon Web Services). Legitimate. |
</threat_model>
