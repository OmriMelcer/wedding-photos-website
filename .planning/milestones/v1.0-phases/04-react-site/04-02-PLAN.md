<objective>
Build the two pure-logic React hooks that own all data-fetching and filtering for the gallery — `usePhotos` (single-shot fetch of metadata.json with loading/error state) and `useFilters` (in-memory filter state + memoized derivation of per-phase and flat-filtered photo arrays). Cover both hooks with Vitest unit tests sufficient to satisfy GALL-01, FILT-01, FILT-02, and FILT-03 acceptance.

Purpose: Plan 03 (UI components) must consume well-tested hooks rather than reinventing fetch and filter logic per-component. Splitting hooks into their own plan keeps filter/fetch correctness verifiable in isolation (pure functions, no DOM, fast tests) and prevents Plan 03 from blowing past context on a single monolithic implementation.

Output: Two hook files + two test files. All four GALL-01/FILT-01/FILT-02/FILT-03 requirements have automated test coverage. `usePhotos` does NOT re-fetch on filter change (the GALL-01 invariant). `useFilters` returns both per-section and flat-ordered arrays so Plan 03's Gallery and Lightbox can both consume them without duplicating filter logic.
</objective>

<!-- Hook signatures and return shapes — Plan 03 components will consume these. -->

usePhotos(): { photos: Photo[], people: Person[], loading: boolean, error: Error|null }
  - On mount: fetch(METADATA_URL), validate Array.isArray(data.photos), set state
  - Empty useEffect deps array — fetch fires exactly once per mount
  - On HTTP non-ok: throw Error with message `HTTP ${status}: ${statusText}`
  - On photos not an array: throw Error with message 'metadata.json: photos field is not an array'
  - On any error: setState { ...state, loading: false, error }; never crashes the component

useFilters(photos: Photo[]): {
  filteredByPhase: { [phase]: Photo[] },           // keyed by phase, values sorted by sort_key asc
  flatFilteredPhotos: Photo[],                      // PHASE_ORDER.flatMap(filteredByPhase[phase])
  selectedPhotographers: Set<string>,               // empty Set = no filter applied (all match)
  selectedPhases: Set<string>,                      // empty Set = no filter applied (all match)
  togglePhotographer: (label: string) => void,
  togglePhase: (phase: string) => void,
  clearAll: () => void,
}
  - Filter semantics: AND across groups, OR within each group (D-09)
  - Memoize: useMemo([photos, selectedPhotographers, selectedPhases]) for filteredByPhase
  - Memoize: useMemo([filteredByPhase]) for flatFilteredPhotos
  - Sort: within each phase, photos sorted ascending by sort_key
  - Order: flatFilteredPhotos follows PHASE_ORDER, then sort_key within phase (= chronological wedding day order for the filtered set)
</interfaces>
