<objective>
Add EXIF stripping to `pipeline/resize.py` so every web-quality output image and thumbnail produced by `resize_photo()` contains zero EXIF data (no GPS, no device identifiers, no timestamps). Source files in `sources/` MUST remain byte-for-byte unchanged.

Purpose: Implements SEC-01 — privacy hardening before the URL is shared with guests. EXIF in JPEGs from phones routinely contains GPS coordinates and device fingerprints; the metadata that matters for the site (photographer, cluster, sort_key) already lives in `metadata.json`, so stripping JPEG EXIF carries no risk of data loss.

Output: Modified `pipeline/resize.py` with `exif=b""` on both `.save()` calls and an extended `pipeline/tests/test_resize.py` with three new unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source camera/phone → pipeline | EXIF metadata (GPS, device serial, timestamps) embedded by capture device crosses into pipeline output |
| Pipeline output → R2 → guest browser | Whatever bytes resize.py writes will be served publicly to anyone with the gallery URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information disclosure | resize.py output JPEGs containing GPS EXIF | mitigate | Pass `exif=b""` to both `.save()` calls in `resize_photo()` (D-01); verified by `test_exif_stripped_web` and `test_exif_stripped_thumb` asserting `dict(result.getexif()) == {}` on re-opened output |
| T-06-02 | Information disclosure | resize.py output JPEGs containing device Make/Model/SerialNumber | mitigate | Same `exif=b""` kwarg strips Make (271), Model (272), SerialNumber; verified by same tests asserting an empty `getexif()` dict |
| T-06-03 | Information disclosure | resize.py output JPEGs containing DateTimeOriginal timestamp | mitigate | Same `exif=b""` kwarg strips DateTime (306) and DateTimeOriginal; verified by same tests |
| T-06-04 | Tampering | Original `sources/*.jpg` files modified by resize.py | mitigate | resize.py opens `src` read-only via `Image.open(src)` and only writes to `web_out` / `thumb_out`; `test_sources_untouched` asserts `src.read_bytes()` is byte-for-byte unchanged after `resize_photo()` runs |
| T-06-05 | Tampering | Pillow `exif_transpose()` writes orientation to wrong path | accept | `exif_transpose()` returns a new in-memory image and does NOT write to disk; no mitigation needed beyond the existing read-only access pattern |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; uses Pillow 12.2.0 already declared in `pyproject.toml` and verified in 06-RESEARCH §Package Legitimacy Audit |
</threat_model>
