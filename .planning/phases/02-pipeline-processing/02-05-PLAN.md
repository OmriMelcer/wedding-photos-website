<objective>
Build `pipeline/resize.py` — Stage 4 (final) of Phase 2. Read pipeline/output/metadata.json (produced by cluster.py), open each source image, correct EXIF orientation, and emit a web-quality JPEG (longest edge ≤ 2000px) and a thumbnail (longest edge ≤ 400px) for each photo. Filenames in the output directories exactly match the `filename` field already set by cluster.py.

Purpose: This stage produces the actual image bytes the Phase 4 React site will display. Output filenames must align with metadata.json so Phase 3 upload.py can pair each metadata entry to its web/thumb image without a separate manifest. Orientation correction is the critical correctness concern — without `exif_transpose`, portrait-oriented photos from phones and DSLRs render sideways in the gallery.

Output: pipeline/resize.py + pipeline/output/photos/*.jpg + pipeline/output/thumbs/*.jpg.
</objective>

    Create `pipeline/resize.py` following the acquire_google.py / ingest.py / embed.py / cluster.py skeleton.

    Module docstring: `"""pipeline/resize.py\n\nResize photos to web quality and generate thumbnails.\nReads pipeline/output/metadata.json for photo IDs and filenames, joins to\npipeline/output/catalog.json to locate each source image, and writes:\n  pipeline/output/photos/{id}.jpg  (longest edge ≤ 2000px)\n  pipeline/output/thumbs/{id}.jpg  (longest edge ≤ 400px)\n\nUsage:\n    uv run python pipeline/resize.py\n\nDependencies:\n    pillow  (EXIF transpose, resize, JPEG save)\n"""`.

    Imports after `from __future__ import annotations`: `json`, `sys`, `pathlib.Path`; then `from PIL import Image, ImageOps`.

    Path constants:
      `_SCRIPT_DIR = Path(__file__).resolve().parent`
      `_PROJECT_ROOT = _SCRIPT_DIR.parent`
      `_CATALOG_PATH = _PROJECT_ROOT / "pipeline" / "output" / "catalog.json"`
      `_METADATA_PATH = _PROJECT_ROOT / "pipeline" / "output" / "metadata.json"`
      `_PHOTOS_DIR = _PROJECT_ROOT / "pipeline" / "output" / "photos"`
      `_THUMBS_DIR = _PROJECT_ROOT / "pipeline" / "output" / "thumbs"`

    Module-level constants: `WEB_MAX = 2000`, `THUMB_MAX = 400`, `JPEG_QUALITY = 82`, `JPEG_OPTIMIZE = True`.

    Implement `resize_photo(src: Path, web_out: Path, thumb_out: Path) -> None`:
      1. `img = Image.open(src)`.
      2. `img = ImageOps.exif_transpose(img)` — correct orientation BEFORE resize. This is non-negotiable; without it, portrait phone photos render sideways.
      3. `img = img.convert("RGB")` — strips alpha channel (JPEG cannot save RGBA) and normalizes palette/grayscale/CMYK to RGB.
      4. `web_out.parent.mkdir(parents=True, exist_ok=True); thumb_out.parent.mkdir(parents=True, exist_ok=True)`.
      5. `web = img.copy(); web.thumbnail((WEB_MAX, WEB_MAX), Image.Resampling.LANCZOS); web.save(web_out, format="JPEG", quality=JPEG_QUALITY, optimize=JPEG_OPTIMIZE)`.
      6. `thumb = img.copy(); thumb.thumbnail((THUMB_MAX, THUMB_MAX), Image.Resampling.LANCZOS); thumb.save(thumb_out, format="JPEG", quality=JPEG_QUALITY, optimize=JPEG_OPTIMIZE)`.

    The `img.copy()` calls are critical — `Image.thumbnail()` modifies in-place; without copying, the thumbnail call would destroy the high-resolution image before the web save (RESEARCH.md Anti-Pattern).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source JPEG → Pillow resize | Same trust boundary as ingest.py — image bytes through Pillow |
| metadata.json + catalog.json → resize.py | Trusted upstream artifacts from this phase's earlier plans |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | Path traversal via metadata.json `filename` field | mitigate | `filename` is set by cluster.py as `f"{id}.jpg"` where `id` is `{label}_{file_stem}`. Since ids are derived from sanitized filesystem names, they cannot contain `/` or `..`. Sanity check in resize.py: `if "/" in photo["filename"] or ".." in photo["filename"]: warn + skip`. |
| T-02-12 | Information Disclosure | Output JPEGs strip EXIF inadvertently | accept | JPEG re-encode via `Image.save(format="JPEG")` does NOT preserve EXIF by default — desired behavior (web images should not leak camera serial numbers, GPS, etc. to the public R2 bucket). |
| T-02-13 | Denial of Service | Memory exhaustion on huge source JPEGs | mitigate | `Image.thumbnail()` streams the resize via PIL's incremental decoder. Pillow does not load full-resolution pixel arrays into memory for downscale operations. |
</threat_model>
