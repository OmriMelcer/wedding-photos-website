<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → config.yaml | Album URLs are user-supplied; malformed URLs could cause gallery-dl to fetch unintended resources |
| gallery-dl subprocess → filesystem | gallery-dl writes files to output_dir; path traversal in filenames could escape the destination |
| Google Photos shared album | Shared album links are public by design; no credential leakage risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | pipeline/config.yaml | accept | Config holds album URLs (public links) and display names only — no credentials in this plan. File is local-only, not committed with real URLs. |
| T-01-02 | Tampering | gallery-dl subprocess / output_dir | mitigate | Resolve output_dir as an absolute path using `Path(script_dir / output_dir).resolve()` and assert it is a descendant of the project root before passing to gallery-dl. Prevents path traversal if config.yaml is tampered with. |
| T-01-03 | Elevation of Privilege | uv add gallery-dl | mitigate | gallery-dl is a well-established open-source tool (GitHub: mikf/gallery-dl, PyPI: gallery-dl). Verify package on PyPI before adding. |
| T-01-SC | Tampering | pip/uv installs (gallery-dl, pyyaml) | mitigate | Verify gallery-dl at pypi.org/project/gallery-dl and pyyaml at pypi.org/project/PyYAML before `uv add`. Both are established packages; treat as CONFIRMED. |
</threat_model>
