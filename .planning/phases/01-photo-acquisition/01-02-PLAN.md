<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → filesystem | gallery-dl fetches content from an external URL and writes to sources/pic_time/; malicious filenames in gallery responses could affect the local filesystem |
| pic-time gallery → script | Open-access gallery — no credentials transmitted; risk surface is download content only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | gallery-dl filename output | mitigate | Use `--filename "{filename}"` to sanitize via gallery-dl's own filename sanitization; OUTPUT_DIR is a resolved absolute path descendant of the project root — gallery-dl will not write outside it. |
| T-02-02 | Information Disclosure | requests fallback (if used) | accept | Only fetches from a known public URL. No credentials are sent. Response content is image files only. |
| T-02-03 | Denial of Service | Large gallery download | accept | One-shot local script. If gallery is very large, the script will take longer but will not cause data loss. Re-run is safe (existing files in OUTPUT_DIR will be overwritten or skipped depending on gallery-dl behavior). |
| T-02-SC | Tampering | pip/uv installs (requests, beautifulsoup4 if used) | mitigate | Both packages are established (pypi.org/project/requests, pypi.org/project/beautifulsoup4). Verify on PyPI before `uv add`. |
</threat_model>
