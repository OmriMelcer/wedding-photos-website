<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> R2 public bucket | Untrusted browser origins (any guest device) issue cross-origin GET requests to fetch metadata.json and image files. |
| developer machine -> Cloudflare API | wrangler CLI uses OAuth credentials to mutate bucket CORS policy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | R2 bucket via browser | mitigate | cors.json sets allowed.methods = ["GET", "HEAD"] only. No PUT/POST/DELETE methods exposed cross-origin. Acceptance criteria check methods array exactly. |
| T-05-02 | Information Disclosure | Photo URLs enumerable by guests | accept | All photos are intentionally public to wedding guests; the album is a public gallery by design (per 05-RESEARCH.md §Known Threat Patterns). |
| T-05-03 | Information Disclosure | wrangler API token in config | mitigate | Use `npx wrangler login` OAuth flow (Task 1). cors.json contains no credentials. pipeline/config.yaml r2 block contains only public values (bucket name, endpoint, public URL) — secrets remain in R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY env vars per existing upload.py pattern. |
| T-05-04 | Elevation of Privilege | Misconfigured CORS allowing writes | mitigate | wrangler r2 bucket cors list (Task 3) must show GET+HEAD only; PUT/DELETE absence is an explicit acceptance criterion. |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. wrangler is already globally installed at v4.92.0 (per 05-RESEARCH.md §Environment Availability); no new dependencies. |
</threat_model>
