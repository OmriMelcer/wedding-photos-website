## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local output dir → R2 → guest browser | Bytes written by pipeline/resize.py are uploaded to R2 by pipeline/upload.py and served publicly to anyone with the gallery URL |
| Shell environment → boto3 S3 client | R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY in env vars cross the boto3 boundary into AWS-SDK signing; credentials grant Object Read+Write on the bucket |
| Stale pre-Phase-6 outputs (with EXIF) → new uploads | If stale .jpg files in pipeline/output/ are NOT cleared, upload.py will re-upload EXIF-bearing JPEGs and Phase 8 fails silently — the threat is operational, not adversarial |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-08-02 | Information disclosure | GPS / device / timestamp EXIF surviving to live R2 photos | mitigate | Task 3 downloads a live R2 photo via curl and asserts `dict(Image.open(...).getexif()) == {}` — fails the verify command if any EXIF is present |
