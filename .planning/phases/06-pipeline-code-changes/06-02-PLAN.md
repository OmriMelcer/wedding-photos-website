<objective>
Add Cache-Control headers to every R2 upload call in `pipeline/upload.py` so guests' browsers and the CDN edge cache photos/thumbnails forever (immutable, content-addressed) and metadata.json for 24 hours.

Purpose: Implements SEC-02 and SEC-03 — CDN efficiency and explicit cache semantics. Photo filenames are content-addressed (`{photo.id}.jpg`), so they can safely be marked `immutable` with a 1-year `max-age`. `metadata.json` mutates on every re-upload, so it gets a 24-hour `max-age` to bound the stale window without round-tripping on every page load.

Output: Modified `pipeline/upload.py` with `extra_args: dict | None = None` plumbed through `_upload_file()` and `CacheControl` set at all three upload call sites, plus a new `pipeline/tests/test_upload.py` covering the helper's ExtraArgs forwarding.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pipeline → R2 (boto3 upload) | Object metadata (ContentType, CacheControl) set at upload time is treated as authoritative by R2 and propagated to all HTTP responses |
| R2 → CDN edge → guest browser | Cache-Control header governs how long edges and browsers retain content before revalidation; stale data here = stale gallery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Spoofing (stale data) | metadata.json served stale by CDN/browser cache after a re-upload | mitigate | Set `CacheControl: public, max-age=86400` on metadata.json upload (D-07) — bounds stale window to 24 h; verified by `test_upload_file_metadata_cache_control` |
| T-06-07 | Denial of service (cost) | Repeated R2 GET requests for unchanging photos by returning visitors | mitigate | Set `CacheControl: public, max-age=31536000, immutable` on photo and thumb uploads (D-06) — browsers and CDN edges cache forever; photo IDs are content-addressed so `immutable` is safe |
| T-06-08 | Information disclosure | Incorrect ContentType causing browser to mis-handle image as something else | mitigate | Explicitly set `ContentType: image/jpeg` on photo/thumb uploads (D-08) and `application/json` on metadata.json; verified by test ExtraArgs assertions |
| T-06-09 | Tampering | boto3 silently dropping `"Cache-Control"` (hyphenated) key | mitigate | Use `"CacheControl"` camelCase (verified in `ALLOWED_UPLOAD_ARGS`); grep gate in acceptance_criteria ensures hyphenated form never appears in source |
| T-06-10 | Tampering | `_upload_file()` receiving `None` and crashing with `TypeError` in boto3 | mitigate | `ExtraArgs=extra_args or {}` pattern (D-05) guarantees a dict is always passed; verified by `test_upload_file_no_extra_args_uses_empty_dict` |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; uses boto3 1.43.9 already declared in `pyproject.toml` and verified in 06-RESEARCH §Package Legitimacy Audit |
